ytDownloader：直接读取 Chrome Cookies

使用 Chrome 当前的登录状态，减少反复导出、复制 Cookies。

io 实测 · 2026 年 11 月 4 日

一次设置，直接读取

  1. 先确认 Chrome 可以播放视频

    在平时使用的 Chrome 个人资料中打开同一条 YouTube 视频。完成登录或网站要求的验证，确认可以正常播放。

  2. 在 ytDownloader 中选择 Chrome

    打开“设置 → 高级工具”，将“选择 Cookie 来源”设为“浏览器”，再选择 Chrome。4.0.1 若只是默认显示 Chrome，可先选择其他浏览器，再切回 Chrome，确保选项真正保存。

  3. 在 macOS 27 授权 Chrome 数据访问

    打开“系统设置 → 隐私与安全 → 文件与文件夹”，展开 YTDownloader，打开 Google Chrome 开关。如果尚未出现该项，先在 ytDownloader 尝试解析一次链接，再回到此处检查。

  4. 重启 ytDownloader 后重新添加链接

    点击设置里的“重启应用程序”。回到首页重新粘贴视频链接，让新任务读取 Chrome 当前的登录状态。

  5. 下载时确认同时包含画面和声音

    选择画质后下载。如果选择的是单独的视频流，还要选择一条音轨，不要保留“无音频”。等任务显示“打开文件”后再检查成品。

这项权限意味着什么

Google Chrome 开关允许软件访问 Chrome 的应用数据，其中包含其他网站的登录 Cookies。仅在你信任该软件时开启。本次 macOS 27 实测只需要这个文件夹权限，无需开启“完全磁盘访问权限”。

仍然失败时，按报错检查

提示“找不到 Chrome Cookies 数据库”

先检查上述 Google Chrome 开关，再重启 ytDownloader。若使用多个 Chrome 个人资料或自定义数据目录，可能还需额外配置，参考官方 Cookies 文档。

提示“登录以确认你不是机器人”

确认已登录的 Chrome 个人资料可以播放同一视频，网站验证在 Chrome 中完成。Cookies 可能在标注的到期日前被轮换或拒绝；直接读取浏览器能减少手动复制，但不保证始终通过验证。

下载的视频没有声音

所选视频流可能不含音轨。重新选择音频格式，再创建下载任务。

这次实际验证了什么

ytDownloader 4.0.1 / macOS 27：授权访问 Chrome 数据后，任务确实使用 --cookies-from-browser chrome，成功下载含立体声音轨的 720p MP4，并通过全片解码检查。实测范围是这一工作流，不代表所有视频或未来的网站变化都能正常处理。
