ytDownloader: Chrome Cookies setup

Use your current Chrome session instead of copying Cookies by hand.

Tested by io · November 4, 2026

Set it up once

  1. Check your Chrome session

    Open the same YouTube video in the Chrome profile you normally use. Sign in and complete any verification the site requests; check that the video plays.

  2. Choose Chrome in ytDownloader

    Open Preferences → Advanced Tools. Set Cookie source to Browser, then choose Chrome. In 4.0.1, if Chrome is only shown as a default, select another browser and switch back to Chrome to ensure the choice is saved.

  3. Allow Chrome app-data access on macOS 27

    Open System Settings → Privacy & Security → Files & Folders. Expand YTDownloader and turn on Google Chrome. If the entry is missing, try parsing a link in ytDownloader once, then check this panel again.

  4. Restart ytDownloader

    Use Restart app in Preferences. Return to the home page and paste the video URL again, so the new task reads the current Chrome session.

  5. Choose both video and audio

    Pick a resolution and download. If you select a video-only stream, also select an audio track instead of No audio. Keep the app open until it shows the completed file.

What this permission allows

The Google Chrome switch grants access to Chrome app data, including login Cookies for other sites. Enable it only for software you trust. Our macOS 27 test needed this specific folder permission; Full Disk Access was not required.

If it still fails

“Could not find chrome cookies database”

Check the Google Chrome permission above and restart ytDownloader. A custom Chrome data folder or multiple profiles may need additional configuration; see the official Cookies documentation.

“Sign in to confirm you’re not a bot”

Check that the same video plays in the signed-in Chrome profile. Complete any site verification in Chrome. Cookies can be rotated or rejected before their displayed expiry date; direct browser access reduces manual copying but does not guarantee access.

The video has no sound

Select an audio track when the chosen video stream does not include audio, then create a new download task.

What was actually tested

ytDownloader 4.0.1 on macOS 27: after enabling Chrome app-data access, the app used --cookies-from-browser chrome and downloaded a 720p MP4 with stereo audio. A full-file decode check passed. This confirms this workflow, not compatibility with every video or future website change.
